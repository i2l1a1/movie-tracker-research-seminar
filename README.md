# Movie Tracker

Movie Tracker - это приложение, которое помогает вести список фильмов и сериалов: что уже посмотрел, что в планах, какую
оценку поставил и когда ждать следующий сезон или часть.

## Запуск

1. Скопировать env:

```bash
cp backend/.env.example backend/.env
```

2. Поднять сервисы:

```bash
docker compose up --build
```

После запуска API доступно по адресу http://localhost:8000. Документация - на http://localhost:8000/docs.

## Тесты

Запустить приложение: `docker compose up --build`

Выполнить для прогона всех тестов:

```bash
docker compose exec api pytest -s
```

## Функциональные требования

1. Система позволяет добавить в коллекцию фильм или сериал с полями `title`, `type`, `status`, `rating` и
   `next_release_date`.
2. Система позволяет удалить существующую запись из коллекции по её идентификатору.
3. Система позволяет обновить у записи поля `title`, `type`, `status`, `rating` и `next_release_date`.
4. Система отдаёт полный список сохранённых фильмов и сериалов по запросу клиента.
5. Система отдаёт одну запись по идентификатору или сообщает, что она не найдена.
6. Если статус «просмотрено», оценка от 1 до 10 допустима, а если «запланировано» - оценка запрещена.
7. Система отдаёт агрегированную статистику по коллекции: счётчики (`total`, `watched`, `planned`, `movies`, `series`) и
   средний рейтинг (`average_rating`).
8. Система позволяет отфильтровать список записей по статусу просмотра (`watched`, `planned`) и типу (`movie`,
   `series`).
9. Система отдаёт записи с датой следующего выхода, отсортированные от ближайших.
10. Система позволяет искать записи в коллекции по подстроке в названии.

## Нефункциональные требования

1. Типовые CRUD-запросы (`POST /movies`, `GET /movies/{id}`, `PATCH /movies/{id}`, `DELETE /movies/{id}`) при
   запуске через Docker Compose и наборе данных нагрузочного теста обрабатываются не более чем за 50 мс каждый.
2. API возвращает ошибки в едином формате: HTTP-код и описание причины ошибки.
3. Обращение к несуществующей записи завершается HTTP 404 без изменения состояния базы.
4. Каждый HTTP-запрос логируется с указанием метода, пути, кода ответа и времени выполнения.
5. Сервис предоставляет механизм проверки работоспособности API и доступности базы данных.
6. Swagger-документация API автоматически генерируется на основе схем эндпоинтов и доступна по адресу `/docs`.
7. Операции создания, изменения и удаления записи выполняются атомарно в рамках транзакции базы данных.
8. Сервис API и PostgreSQL поднимаются совместно с помощью Docker Compose.
9. Ответы API сериализуются в JSON с устойчивой схемой полей для интеграции с фронтендом или другими приложениями.
10. Эндпоинты покрыты автотестами, есть нагрузочный тест на 100000 записей с замером времени (запросы выполняются не
    более чем за 50 мс).
